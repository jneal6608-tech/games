# Lurelight

Arcade survival roguelite for Android. You are a small anglerfish in the deep sea and your glowing lure is your
only weapon: circle your thumb to whirl it through swarms, level up, mutate, and dive as deep as you can.

Engine: **Godot 4.7** (free, MIT). Everything is text (GDScript scenes and code), so the project opens directly in
the Godot editor: *Import* > select `project.godot`.

## Status: v0.2.0, feature-complete for a first release

Done:
- Core loop: floating joystick, lure physics, 6 creature types, elites, 3 bosses, 4 depth zones then endless trench
- 11 mutations (each one changes how the lure looks), level-up choice screen with rerolls
- Progression: pearl shop (6 permanent upgrades), 3 unlockable fish with their own lure handling, cosmetic lure glows
- Retention: 25 awards, 7-day daily reward, daily dive with streak bonus
- Monetization: optional rewarded ads (revive, double pearls, reroll, double daily reward), paced interstitials
  between dives, Remove Ads and Starter Pack purchases. AdMob runs on Google's test ad units until real ids are set
- Menu, pause, settings, end-of-run card, first-run hints, clip mode (hides the HUD for screen recordings)
- Original art (SVG), sound effects and music (generated by `tools/gen_audio.py`)
- Signed release `.aab` and `.apk`, store listing, screenshots, privacy policy, publishing guide (`store/`)

Not built yet:
- The idle reef (offline pearls), Google Play Games sign-in and leaderboards
- iOS

**Never run on a physical Android phone, and real ads and real purchases have never been exercised.** What has
been tested and how is in the table at the top of `store/PUBLISHING.md`.

## Run and build

```bash
godot --path .                       # play on desktop (mouse = touch, arrow keys also steer)
tools/setup_toolchain.sh             # one-time: Godot, export templates, Android SDK, debug key
GODOT=~/.local/lurelight-toolchain/Godot_v4.7-stable_linux.x86_64 tools/build_apk.sh
```

The Android build is a Gradle build (the ad and billing plugins need one). The scripts unpack Godot's build
template into `android/` (git-ignored); the first build downloads Gradle and the Android libraries.

Release (signed `.aab` for Google Play plus an `.apk`), after `tools/make_keystore.sh` has been run once:

```bash
GODOT=... KEYSTORE=build/signing/lurelight-release.keystore KEYSTORE_PASS='...' tools/build_release.sh
```

`store/PUBLISHING.md` is the full path to Google Play.

Install `build/lurelight-debug.apk` on a phone (allow "install unknown apps" for your file manager or browser).

### Browser build (for iPhone or desktop testing)

```bash
godot --headless --path . --export-release Web build/web/index.html
```

Needs the `web_nothreads_*` export templates. Upload the contents of `build/web/` (zipped) to any static host,
for example an itch.io HTML game page, and open it in the phone's browser. It is single-threaded, so no special
server headers are needed. The web preset's `html/head_include` reserves 288 MB of memory at load, because iPhone
Safari kills the page if the game's memory has to grow mid-dive. It is a test convenience, not a release target: no vibration, and performance is not
the same as the native app.

## Developer flags

Pass after `--`, for example `godot --path . -- --autoplay --log --quit-after=300`:

| Flag | Effect |
| --- | --- |
| `--autoplay` | Start a dive with the automated player |
| `--log` | Print depth, kills, level and frame rate every 15 s |
| `--quit-after=N` | Quit after N seconds and print a result line |
| `--bench` | Print lure speed for scripted thumb motions at 30/60/120 fps |
| `--screen=NAME` | Open `menu`, `levelup`, `end`, `pause` or `settings` |
| `--shots=DIR --shot-times=2,10` | Save screenshots |
| `--zone=N`, `--hearts=N` | Start deeper, or with more hearts |
| `--zone-t=N`, `--muts=heavy:2,twin:1` | Start N seconds into the zone, or with mutations (store screenshots) |
| `--fish=ID` | Play as `angler`, `brute`, `whip` or `twin`, owned or not |
| `--nometa` | Ignore pearl-shop upgrades (baseline balance runs) |
| `--fakeads`, `--fakestore` | Simulate ads that always pay out, and a store where purchases succeed |
| `--uitest` | Scripted test of every screen, saving, the shop, awards and (with the two flags above) ads and purchases |
| `--screen=NAME` also takes | `shop`, `fish`, `awards`, `reward`, `revive`, `store` |

`tools/run.sh` wraps Godot in a virtual display for machines without a screen.

## Layout

| Path | What |
| --- | --- |
| `src/main.gd` | Entry point: screen flow, touch input, dev flags |
| `src/game/world.gd` | One dive: spawning, collisions, level-ups, zones, bosses |
| `src/game/lure.gd` | Lure physics and drawing |
| `src/game/enemy.gd` | Creature definitions and behaviour |
| `src/game/mutations.gd` | In-dive upgrade list |
| `src/game/meta.gd` | Everything between dives: shop upgrades, fish, glows, awards, daily rewards (all the numbers) |
| `src/autoload/ads.gd`, `admob_backend.gd` | Ad interface and pacing rules; the AdMob implementation |
| `src/autoload/store.gd` | Purchases (Google Play Billing) |
| `addons/` | Third-party Android plugins: AdMob (Poing Studios, MIT) and Google Play Billing (Godot, MIT) |
| `store/` | Listing text, graphics, privacy policy, publishing guide |
| `src/ui/` | HUD, menus, shared styling |
| `src/autoload/` | Save file, audio |
| `assets/` | Art (SVG), audio, fonts (SIL Open Font License) |
| `tools/` | Audio generator, build and test scripts |

## Tuning

Most balance numbers are constants at the top of `world.gd` (spawn table, zone lengths, damage) and in
`Enemy.DEFS`; prices, fish stats and rewards are in `meta.gd`. After changing lure physics, run `--bench`; after changing balance, run
`--autoplay --log --quit-after=420 --fixed-fps 60` headless and compare the result line.
